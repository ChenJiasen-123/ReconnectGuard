## 需要共同确认的接口问题

这些是接入前必须确认的设计项，不是已经实现的能力：

- run_id 只有一个生成者。推荐真实平台生成，Runner 复用；避免 Lab 和 Runner 各建一轮目录。
- event_id 和 seq 由统一记录器分配。seq 在单轮内递增，mark 返回该序列的游标。请求事件和观测事件使用同一排序约定。
- attempt_id 表示测试器有证据区分的连接尝试，不等同于每次协议重传。无法归属时为 null，不能强行标记当前尝试。
- source=sta 表示客户端证据来源，即使由 Observer 生成标准化事件，也须保留原始证据引用。AP 证据单独保存。
- baseline_confirmed / connection_restored 需要当前客户端状态数据；不能仅由命令回执生成。双端和数据通信检查应作为额外检查项。
- 单调时钟用于本机超时和时长，墙钟用于人工对照。跨主机单调时钟不能直接比较。
- 当前 ActionReceipt 只有动作编号、动作名、接受结果和效果状态。真实接口还需约定 run_id、attempt_id、目标端、原始响应、时间及错误类别。
- 当前 Context 的缓存和授权字段是占位值。真实快照映射、状态更新策略、证据时间及有效范围尚未实现。
- 真实后端错误必须区分动作拒绝、观测超时、进程退出、采集失败及清理失败。日志保存失败也应显式报告。

## 实际接入时的已知风险

- EFSM 的重复判断依据 event_id。不同 event_id 的同义事件仍可能触发非法转换，真实 Observer 需定义标准化和去重策略。
- EFSM 先检查转换规则，再检查来源。Observer 当前会先过滤来源；直接向 EFSM 投递无关原始事件可能抛出 InvalidTransition。真实接入前应明确忽略与报错规则。
- 当前模型不单独检查时间戳倒序；游标不是无线事件真实发生时间的证明。
- mock 立即产生事件并使用虚拟时钟，未验证真实排队、迟到、丢事件或并发行为。
- 当前进程连续性只是固定模拟标识。真实实现必须使用平台进程世代信息。
- 输入只支持 YAML 1.2 的 JSON 子集；扩展 YAML 或步骤时必须同步校验器和测试。

## 后续模型扩展原则

保持流程状态、双端观测、安全属性判断分离。完整 SAE、关联和密钥建立作为可观测子阶段；没有相应证据时不补造中间转换。授权检查必须有本次尝试的认证与密钥确认依据，不能仅看最后 COMPLETED。

为缓存条件增加明确变量、来源与更新时间，随后定义变量如何影响动作和转换条件。缓存存在不代表有效，也不代表被使用。合法缓存保留不自动判为异常。

异常事件先记录事实，再由独立判定器给出恢复失败、证据不足、环境错误或候选安全异常。对候选异常另行复测。
